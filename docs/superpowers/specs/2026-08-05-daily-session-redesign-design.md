# 오늘의 학습 화면 UI/디자인 개선 — 설계 문서

## 배경 및 목적

Task 19까지 구현된 "오늘의 학습" 화면은 기능적으로는 완성됐지만, 스타일링이 거의 없는
상태(기본 Next.js 스캐폴딩 CSS만 존재)라 모든 교재의 문제·서술형·어휘가 번호도 없이
하나의 긴 목록으로 뒤섞여 나온다. 실제 사용해보니 가독성이 크게 떨어져, 화면을
다시 디자인한다.

브라우저 기반 시각 브레인스토밍(visual companion)으로 여러 시안을 직접 보면서 방향을
좁혀나갔다.

## 범위

- `src/app/page.tsx`의 레이아웃/스타일 전면 개편
- 새로운 "표지(cover)" 진입 화면 추가 (로그인 후, 문제 화면 진입 전)
- 교재별 섹션 구분, 문제 번호, 세로 나열 보기 등 정보구조 개선
- 색상/타이포그래피 등 비주얼 스타일 적용

**범위 밖 (이번 개선에 포함하지 않음):**
- 빈출 오류 정리("오답노트") 기능 — 별도 브레인스토밍/스펙으로 진행
- `/api/progress` 연동, 회독 진행률 실제 갱신 — 기존에 확인된 별도 이슈, 이번 스코프 아님
- 다크모드 대응 — `globals.css`에 CSS 변수는 이미 있으나, 이번 개선에서는 라이트 모드
  기준으로만 작업하고 다크모드는 후속 작업으로 남긴다

## 디자인

### 1. 전체 흐름 — 표지 → 본문

기존: PIN 로그인 → 바로 문제 목록이 쏟아지는 화면.

변경: PIN 로그인 → **표지 화면** → "오늘의 학습 시작하기" 버튼 클릭 → **본문 화면**.

표지 화면은 노트를 펼치기 전 겉표지를 보는 느낌을 준다. 화면에는 오늘 날짜, "오늘의
학습" 타이틀, 오늘 배정된 교재별 회독 범위 요약(예: "📘 문법 · 11~19p")만 간결하게
보여주고, 하단에 큰 CTA 버튼 하나("오늘의 학습 시작하기 →")를 둔다. 버튼을 누르면
본문 화면으로 전환된다. 이 전환은 별도 라우트가 아니라 `page.tsx` 내부의 클라이언트
상태(`started: boolean`)로 처리한다 — 데이터는 이미 표지 단계에서 로드해두고, 화면만
전환한다.

### 2. 색상 & 타이포그래피

- 배경: 뽀얀 화이트(`#fbfaf7`, Cloud Dancer 계열 오프화이트)
- 포인트 색(버튼, 뱃지, 강조 텍스트): 틸(청록, `#0f9488`)
- 텍스트: 다크 그레이(`#3a352c` 계열, 순검정 대신 눈이 편안한 톤)
- 폰트: Pretendard (한글에 최적화된 둥글고 가독성 좋은 폰트). `next/font`로 로드하거나
  CDN `@font-face`로 추가한다.
- 문제 카드 배경에는 은은한 노트 줄무늬(반복되는 연한 가로선, `repeating-linear-gradient`)를
  넣어 "학습 노트" 느낌을 준다. 줄무늬는 시안 중 "은은한" 버전으로 — 너무 진하지 않게.

### 3. 정보 구조 — 교재별 섹션 + 번호

본문 화면은 다음 순서로 구성된다:

1. 오늘의 회독 범위 요약 카드 (교재별 아이콘 + 이름 + 페이지 범위, 표지에서 본 것과 동일 정보를 본문에도 짧게 다시 보여줌)
2. 교재별 섹션 (문법 → 문학개론 → 어학개론 순, `assembleDailySession`이 반환하는 `questions` 배열을 `book_id` 기준으로 그룹핑해서 렌더링)
   - 각 섹션은 아이콘 + 교재명 + 페이지 범위 헤더로 시작
   - 섹션 안의 각 문제는 **Q1, Q2, Q3...** 번호를 붙인다 (섹션 내부 순번, 전체 통합 번호 아님)
   - 객관식/카드형 문제: 보기(A/B/C/D 상당)를 세로로 하나씩 쌓아 나열 (현재의 가로 나열 버튼 대신)
   - 서술형 문제가 있는 섹션은 일반 문제 목록 뒤에 점선으로 구분하고, "서술형" 뱃지를
     붙인 뒤 1단계(한국어)/2단계(중국어) 입력창과 제출 버튼을 배치 — 기존 로직(별도
     `/api/attempts/essay` 제출, `content_score`/`chinese_score`/`feedback` 표시)은
     그대로 유지, 시각적 틀만 새 스타일에 맞춘다
3. 오늘의 어휘 카드 — 기존과 동일하게 "AI 큐레이션" 뱃지로 명확히 구분, 맨 아래 배치

### 4. 컴포넌트 분리

`page.tsx` 하나에 모든 로직이 몰려 있던 기존 구조를, 다음과 같이 나눈다 (Task 19의
API 응답 형태 `{ session, questions, vocab, bookRanges }`는 변경하지 않는다 — 프론트
컴포넌트 구조만 재정리):

- `src/app/page.tsx` — 데이터 페칭, 표지/본문 상태 전환만 담당하는 얇은 컨테이너
- `src/app/components/CoverScreen.tsx` — 표지 화면
- `src/app/components/BookSection.tsx` — 교재 섹션 하나(문제 번호, 세로 보기, 서술형 포함)
- `src/app/components/QuizQuestion.tsx` — 객관식/카드형 문제 1개 (제출 + 정오답 피드백)
- `src/app/components/EssayQuestion.tsx` — 서술형 문제 1개 (2단계 입력 + 제출 + 채점 결과)
- `src/app/components/VocabCard.tsx` — 오늘의 어휘 카드
- 스타일은 `src/app/page.module.css`를 재활용(현재 스캐폴딩 잔재를 지우고 새 스타일로
  교체)하거나 CSS 변수를 `globals.css`에 추가하는 방식으로 처리 — Tailwind 등 새 의존성은
  도입하지 않는다 (YAGNI, 지금 규모에서 CSS Modules로 충분)

### 5. 에러 처리

기존 에러 상태(`오늘 학습 콘텐츠를 불러오지 못했어요. 새로고침 해주세요.`)는 표지
화면 단계에서 동일하게 표시한다 (데이터 페칭은 표지 화면 진입 시점에 이미 시작되므로,
실패 시 표지 화면 자리에 에러 메시지를 보여준다).

### 6. 테스트

- 기존 `src/app/page.test.tsx`의 4개 테스트 케이스는 컴포넌트 구조가 바뀌므로 새 구조에
  맞게 다시 작성한다 (표지 화면 렌더 → "시작하기" 클릭 → 본문 렌더 → 문제/서술형/어휘
  검증까지, 사용자 흐름 전체를 따라가는 통합 테스트로)
- 새로 분리되는 컴포넌트(`BookSection`, `QuizQuestion`, `EssayQuestion`, `VocabCard`)는
  각각 최소 1개 이상의 단위 테스트를 추가한다
